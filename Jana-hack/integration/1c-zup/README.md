# Расширение 1С:ЗУП для JanaМен

Этот каталог — передаваемый комплект для специалиста 1С. Он фиксирует внешний контракт `jana-zup-v1`, но не привязан к именам объектов конкретного релиза ЗУП. Объекты начислений, остатков и документов отпуска специалист сопоставляет в тестовой копии базы.

## Что добавить в расширение

HTTP-сервис `JanaZup`, корневой URL `jana/v1`, с шаблонами и методами:

| Шаблон | Метод | Обработчик |
| --- | --- | --- |
| `/employees` | GET | `EmployeesGET` |
| `/employees/{employee_id}/leave-balance` | GET | `LeaveBalanceGET` |
| `/leave/calculate` | POST | `LeaveCalculatePOST` |
| `/leave/documents` | POST | `LeaveDocumentsPOST` |

Шаблон модуля находится в [HTTPServiceModule.template.bsl](HTTPServiceModule.template.bsl). Он решает HTTP/JSON-часть. В общем серверном модуле `JanaZupIntegration` нужно реализовать четыре функции, отмеченные в шаблоне. Это единственное место, зависящее от релиза и доработок конкретной ЗУП.

В расширении также нужен регистр сведений для идемпотентности со следующими полями:

- `CommandKey` — строка 128, уникальный ключ;
- `PayloadHash` — строка 64;
- `DocumentReference` — строка 100;
- `AppliedAt` — дата-время.

Регистрация отпуска выполняется в одной транзакции: проверить ключ и hash тела, рассчитать период заново, проверить остаток/пересечение, создать и провести документ, записать ключ и номер документа. Повтор того же ключа и тела возвращает прежнюю квитанцию. Тот же ключ с другим телом возвращает HTTP 409.

## Публикация

1. Подключить расширение к тестовой копии ЗУП и не снимать конфигурацию с поддержки.
2. Создать отдельного пользователя 1С с правами только на нужные чтения, расчёт и создание выбранного вида отпуска.
3. Опубликовать HTTP-сервис через Apache/IIS по HTTPS. Итоговый адрес имеет вид `https://host/base/hs/jana/v1`.
4. Выбрать Basic-аутентификацию 1С либо Bearer через корпоративный шлюз. Не включать анонимный доступ.
5. С машины или контейнера JanaМен выполнить только чтение:

Задать `ZUP_MODE=real`, `ZUP_BASE_URL`, тип аутентификации и сервисный секрет в локальном `.env` с правами `0600`, затем выполнить:

```bash
PYTHONPATH=backend python -m app.check_zup
```

Для проверки конкретного сопоставления и расчёта без записи документа:

```bash
PYTHONPATH=backend python -m app.check_zup \
  --employee-id 'GUID-ИЗ-1С' --start 2027-03-20 --end 2027-03-25
```

Команда никогда не вызывает `/leave/documents`. После её успешного результата отдельно проверяют создание отпуска на тестовом сотруднике, повтор того же `Idempotency-Key`, таймаут после проведения и восстановление ответа.

## Обязательные ответы

- Остаток: `employee_id`, целое `balance`, массив `applied_commands`, `source:"zup_http"`.
- Расчёт: те же поля плюс `days_count`, `calendar_days`, `excluded_dates`, `calendar_version`.
- Квитанция: `reference`, исходный `command_key`, `status:"registered"`.
- Ошибки бизнес-проверок: JSON `{"detail":"безопасный текст"}` и код 409 или 422.

Список `applied_commands` должен соответствовать тому же снимку, что и `balance`. Это защищает остаток при ситуации, когда документ в 1С проведён, а HTTP-ответ потерян.
