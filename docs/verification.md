## Обновлённая веб-панель · 6 октября 2026

Пакет React после `a96d32e` (первого Flutter-клиента). Среда: Windows, Node.js 24.12.0, pnpm 11.19.0, Vite 6.4.3; действующий API на отдельной синтетической SQLite-базе. Сервер, миграции и Flutter этим пакетом не изменялись.

- `pnpm test`: **11 passed**. Проверены отказ 422, неизвестный результат POST при обрыве/500/нечитаемом ответе без автоматического повтора, отбрасывание старых ответов и старого 401 при смене сессии, текущий 401, группы внимания, сортировка свободных работников и следующие действия. Отдельная регрессия: переход из аналитики сохраняет точные ISO-границы смены; ручная дата охватывает день предприятия UTC+05.
- `pnpm run build`: TypeScript и production Vite успешно. Предупреждение о крупном JS-блоке с графиками остаётся; оно не является ошибкой сборки.
- Через браузер пройден настоящий цикл: мастер выдаёт внеплановый наряд из строки Алексея Кима → выбранный работник принимает/начинает → загружает синтетическое фото PNG, клиент отправляет JPEG → сдаёт текст, код неисправности и 2 болта → мастер выбирает оценку 5 и закрывает. В API подтверждены один созданный наряд, `closed`, оценка 5, расход 2 и JPEG. Это проверка интерфейса и доставки, не качества распознавания фотографии.
- Переход с главной «На приёмке» отбирает ожидающие работы. Отчёт «Смена» и переход «Наряды выборки» показали одинаковые **18 нарядов**, включая 2 закрытых. CSV/XLSX по тем же границам через HTTP содержат по 18 строк; XLSX разобран `openpyxl`. Нажатие CSV в встроенном браузере не дало подтверждённого события скачивания, поэтому сохранение файла браузером отдельно не утверждается.
- Проверены вход/выход, отдельная роль исполнителя и роль руководителя: у руководителя нет кнопок выдачи в главной/сотрудниках и кнопок изменения в карточке. У работника вне смены кнопка назначения отключена.
- Визуально проверены главная при 1440×900 и 390×844, мобильные вход/меню/выдача/карточка. На проверенных узких экранах нет горизонтального переполнения документа или диалога. Канбан заменяется вертикальными карточками. Tab/Shift+Tab замыкаются внутри формы, фокус возвращается после её закрытия; скрытая навигация отсутствует в дереве доступности.
- Исправлены найденные при ревью потери обновления во время текущего опроса, зависимость локального выхода от ответа сети и перенос ISO-границ в поля календарных дат. Запрос обновления после действия выполняется ещё раз после уже идущего чтения; выход очищает данные сразу. Изменение токена в другой вкладке перезагружает сессию.

Детерминированные проверки сетевых ошибок относятся к API-клиенту; полноценное отключение сети во время каждого шага формы и восстановление WebSocket здесь отдельно не воспроизводились. Не проверялись PostgreSQL-конкуренция, физические устройства, экранный диктор, увеличенный системный шрифт, производственная сеть и SLA. Лимит 5000, текущая серверная семантика аналитики и ИИ-заглушка сохраняются. UI-защита повторов не заменяет будущую серверную идемпотентность и офлайн-очередь.

## Первый Flutter-клиент · 6 октября 2026

Среда: Windows, Flutter 3.47.0 / Dart 3.13.0, отдельный локальный API с синтетической SQLite-базой. Серверный код этим пакетом не изменялся.

- `flutter analyze --no-pub`: **No issues found**.
- `flutter test --concurrency=1`: **31 passed, 1 skipped**. Live-тест пропускается без `LIVE_API_URL` намеренно. После этого добавлена регрессия перехода из рейтинга: файл `workspace_test.dart` отдельно — **5 passed** вместо прежних четырёх; итого проверено 32 разных клиентских теста.
- `flutter test test/live_api_test.dart --dart-define=LIVE_API_URL=http://127.0.0.1:8000`: **1 passed**. Настоящий Dart HTTP-клиент: мастер создаёт аварийный наряд → worker2 принимает/начинает → фото до/после → работы/материалы → `ai_review` → мастер закрывает с оценкой. Проверены JPEG с авторизацией, события, уведомления и отметка чтения, запрет чужого работника/закрытия работником, 422 без обязательного фото, dashboard/analytics.
- Формы: не отправляют неполные обязательные поля, не назначают работника молча; известный id сохраняется при сбое фото. Повтор загружает только отвергнутый снимок, не пересоздаёт наряд; неизвестный исход записи блокирует слепой повтор. Доработка не подставляет прежние материалы как новый расход. Системный Back после ввода текста предупреждает о потере формы; регрессия сначала воспроизведена, затем исправлена.
- Сессии: проверены отбрасывание старых ответов, смена пользователя во время записи, очистка при 401 и выход с защищённого экрана к логину. Успешная запись остаётся успешной при ошибке последующего чтения.
- `flutter build apk --debug`: успешно, Android APK сформирован. Сборка потребовала ограничения Gradle до 1 ГБ heap/одного worker на машине с 6 ГБ RAM. Установка и запуск на физическом телефоне не проверялись.
- Production-сборка Flutter web прошла. В браузере на ширине 390 × 844 визуально проверены вход, главное рабочее место мастера, форма выдачи, переход к приёмке, карточка и главное рабочее место исполнителя после отдельного входа. Widget-тест на ширине 360 обнаружил переполнение шапки; исправление проверено.

Это не испытание на физическом телефоне, настоящей камеры, Keychain/Android secure storage, фоновой доставки или плохой мобильной сети. PostgreSQL-конкурентность, iOS-сборка, TalkBack/крупный шрифт, SLA 5/10 секунд и 6 нажатий здесь не подтверждены. ИИ остаётся заглушкой. Данные тестов синтетические; веб-превью не подменяет Android-приёмку.

## Историческая проверка прототипа · 5 октября 2026

Ниже сохранён предыдущий отчёт без закреплённого SHA. Его ограничения и прежнее решение оставить заглушки относятся к состоянию прототипа, а не к новому полному объёму.

Проверено на Python 3.12, Node.js 24 и PostgreSQL 17.

- Сервер: `pytest -q` — **20 тестов прошли**. Покрыты жизненный цикл, разграничение ролей, изоляция исполнителей, обязательное фото после внепланового ремонта, проверка изображений, защищенная выдача фото, отзыв сессий HTTP/WebSocket, уведомления и пороги эскалации, простой оборудования, безопасность CSV/Excel и целостность справочников.
- Реальный HTTP API с PostgreSQL: `python3 scripts/smoke_api.py` — успешно. Проверена цепочка создания, принятия, начала, отчета с фотографией и приемки мастером, история, записи справочника после seed и действительная структура XLSX.
- `tsc -b` и production-сборка Vite — успешно. TypeScript-контракт `native-stub/` проходит отдельную проверку типов.
- `docker compose up -d --build`: PostgreSQL, FastAPI и nginx/React запущены; все три healthcheck успешны.
- Через браузер пройден полный цикл планового наряда от создания до закрытия с оценкой мастера. Проверены фильтрация оборудования по участку, показ загрузки исполнителей, поиск, хронология и маркировка ИИ-заглушки.
- Проверены отчет за текущую смену, графики и режим руководителя без кнопок создания; вход и выход работают через nginx на порту 8080.
- Интерфейс проверен при ширине 1440 и 390 пикселей. На мобильной ширине документ не имеет горизонтального переполнения; канбан прокручивается внутри своего блока.
- Начальная миграция Alembic проверена на пустой SQLite-базе; PostgreSQL SQL для начальной схемы успешно сгенерирован. Работа ORM с реальной PostgreSQL отдельно проверена сквозным тестом.

Оставшиеся предупреждения инструментов: библиотека Starlette выдает предупреждение об устаревшем алиасе AnyIO; Vite сообщает о крупном JavaScript-блоке с графиками (около 208 КБ gzip). Эти предупреждения не мешают сборке или проверенным сценариям.

Проверки выполнялись на синтетических данных. Нагрузочные измерения, испытания в производственной сети и на физических Android/iOS устройствах не проводились. Нативный клиент, доставка push и нейросетевые функции намеренно оставлены заглушками.
