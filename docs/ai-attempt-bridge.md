# Мост проверки конкретной сдачи

Пакет после интеграции `43ecb93` выполняется в прежней `feature/order-versions`. Основной сервер остаётся единственным владельцем прав, состояния наряда, очереди задач и финального решения мастера. Изолированный демонстрационный сервис и его `BackendDataSource` не получают общий доступ к рабочей базе.

## Контракт пакета

- Новая nullable `submission_attempts.ai_input` содержит известный контекст, сохранённый в транзакции сдачи: исходные поля наряда, версия на момент сдачи, назначение, справочник шифров и идентичность связанных фото. Старые попытки остаются с null; их исходное задание не восстанавливается из изменившейся карточки. Сам `payload` остаётся прежним отчётом с добавочным расходом попытки.
- Существующие `stub` задачи обслуживает прежняя заглушка. Новые задачи получают `provider=ai_service` только при явно выбранном `AI_REVIEW_MODE=queued_service`; настройки адреса и server-only токена обязательны. По умолчанию остаётся `queued_stub`. Смена настройки не перепривязывает уже сохранённые задачи.
- Stateless `POST /internal/v1/submission-review` принимает только server-generated envelope версии 1: `attempt_id`, `order_id`, frozen `context`, `report`, метаданные связанных `photos` и `input_sha256`. Хеш — SHA256 UTF-8 JSON без самого `input_sha256`, с `sort_keys=True`, `separators=(',', ':')`, `ensure_ascii=False`, `allow_nan=False`. Ответ повторяет версию/attempt/hash и содержит проверенный `result`. Ошибка идентичности не становится оценкой другой попытки.
- Сервис запускается отдельной лёгкой factory; существующие runtime-policy и запрет общего BackendDataSource сохраняются. Он повторно использует функции текстовой проверки уже написанного модуля. По умолчанию внешние LLM-запросы отсутствуют; выбор/разрешение внешней обработки Q01 остаются открытыми. Не называем реальные входные данные синтетическими ради обхода защиты.
- Этот ограниченный пакет передаёт ID/вид/SHA256 фото, а не пиксели, URL или пути. Содержимое изображений, глобальные дубликаты и оборудование этим endpoint не анализируются. CV/vision остаются следующим связным пакетом с отдельным бюджетом времени; существующее разрешение повторного использования фото после доработки сохраняется.
- Отсутствие утверждённых активных интервалов/материальных норм остаётся неизвестностью. `started_at → completed_at` не используется как реальное время работы. Рейтинг, нормы предприятия и правила Q02–Q05 не меняются.

## Результат и безопасность

`accepted → passed`, `accepted_with_remarks → needs_attention`, `needs_rework → needs_rework`, `needs_master_review → needs_attention` с `score=null`. Исходный `source_verdict`, `llm_used`, `is_recommendation=true` и фактический `is_stub` сохраняются в JSON попытки; численная оценка ИИ nullable и не подставляется вместо оценки мастера. Правила/fallback явно помечены заглушкой; модель не выбирает своё происхождение. Новая миграция сохраняет прежние численные оценки и связи. Финальный `close` по-прежнему требует ручную оценку мастера.

HTTP выполняется после commit захвата задачи, без SQL-lock на время обращения. Общий сетевой deadline 8 секунд меньше lease 30 секунд; injected семантический обработчик ограничен 6 секундами. Автоматических транспортных повторов, redirect и proxy из окружения нет, ответ ограничен. Сервисный токен не попадает в клиенты, результаты, ошибки или логи. Ответ принимается только при прежнем lease/текущей попытке/назначении; прежние ключи, отчёты, списания, фото и исходные версии не меняются. Подтверждённый SHA256 входа и версия протокола сохраняются вместе с результатом попытки.

## Запуск и границы готовности

В отдельном окружении из `ai_service/`: `uvicorn app.attempt_bridge:create_attempt_app --factory --host 127.0.0.1 --port 8010`. На обеих сторонах нужен одинаковый `AI_SERVICE_TOKEN`. На основном сервере дополнительно `AI_SERVICE_URL=http://127.0.0.1:8010` и `AI_REVIEW_MODE=queued_service`. Не включать этот режим для чужого адреса; HTTP без TLS предназначен для доверенного loopback/внутренней сети, удалённая связь требует HTTPS. Внешний нейросетевой провайдер этим запуском не включается.

Целевые проверки и один CI окончательного коммита фиксируются в verification после фактического прогона. Наличие этого контракта не означает завершённых испытаний, настоящего LLM/CV или всего кейса. PR #5 уже слит; новые ветки/PR для пакета не создаются, CI ветки запускается вручную.
