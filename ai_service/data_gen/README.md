# Генератор синтетики

`python -m data_gen.generate` запускается из `ai_service/` и не обращается к сети или backend. Фиксированный seed `20261007`, фиксированный период создания: 1 июля — 29 сентября 2026 UTC. Каждый запуск полностью пересоздаёт локальный `data/` и эталоны `eval/cases/`; исходные файлы других компонентов не затрагиваются.

## Состав

| Набор | Количество | Формат |
| --- | ---: | --- |
| Участки / оборудование | 4 / 25 | Поля `Area` и `Equipment` API |
| Мастера / работники / руководитель / бригады | 2 / 15 / 1 / 3 | Поля `Employee` и `Brigade` API; имена — псевдонимы, не ФИО |
| Шифры / материалы / нормативы времени | 20 / 40 / 20 | Поля `FaultCode`, `Material`, `TimeNorm` API |
| Наряды | 719 | `OrderDetail` с событиями, расходом, фото, двумя сменами |
| Нормы материала | 43 связи, все 40 материалов покрыты | Отдельный sidecar `data/material_norms.json`, поскольку в backend такой таблицы нет |

`data/snapshot.json` читается `SyntheticDataSource`; `data/csv/` содержит те же записи по коллекциям. `data/photos/orders/` содержит 719 небольших процедурных PNG «после» и дополнительные рисунки «до» примерно для трети внеплановых нарядов, по путям из `photos[].path`. Снимок и файлы фото не коммитятся, чтобы не засорять репозиторий. Эталонные JSON в `eval/cases/` и `data_gen/ground_truth/patterns.json` хранятся в Git. Генератор валидирует снимок через Pydantic.

Эталон сроков перечисляет все ожидаемые события на всём 180-минутном интервале тиков. В наборе verification базовый расход равен норме материала для шифра; целевой перерасход вносится отдельно. Разметка остаётся синтетической и зависимой от учебной политики.

## Заложенные сигналы

- Конвейер К-3: 60 внеплановых работ против медианы 20; доля М-02 — 68,3%.
- E-11: 25 исходных ремонтов, 7 специально созданных повторов через два дня и 3 поздних повторных наряда через девять дней. Фактически 10 из 25 ремонтов (40%) имеют повтор того же шифра на том же оборудовании ≤7 дней; у остальных — 53 из 544 (9,7%). Эти доли вычисляет генератор с учётом фоновых работ.
- Насос НС-01: 12 внеплановых работ через два дня после 12 плановых; другие фоновые работы не исключены.
- Ночная смена бригады 2: рассчитанная доля опозданий 36,8% против 16,9% у остальных в текущем seed.
- E-04: расход подшипника и смазки по соответствующему шифру увеличен в 2,5 раза.
- Для проверки будущего рейтинга мастерские оценки работ E-04/E-11 заданы ниже остальных; это искусственная разметка, а не вывод из расхода материала.
- Мельница МШЦ-3600: добавлены 12 заказов в последний месяц, из них 18 внеплановых в этом месяце с учётом фона.
- Приманки: однодневный кластер трёх заказов на другой дробилке, одно ночное опоздание бригады 1, одно списание 4×. Это единичные всплески, не эталон устойчивой системной причины.

Точные измеренные значения записываются в `ground_truth/patterns.json`, а не выдумываются моделью. Однако синтетика **не доказывает** точность на производственных данных, причинную связь или реальную сохранность оборудования. `downtime_minutes` — учебная величина, не подтверждённый интервал простоя по решению Q04.

## Фото

`python -m data_gen.photos` создаёт 48 технических пар: точный дубль, JPEG-пережатие, небольшой кроп и другое изображение. Без исходников используется процедурная графика. Для вариаций реальных фото запускайте `python -m data_gen.photos --source-dir <локальная_папка>`; исходники не копируются в Git, а сгенерированные варианты игнорируются. Не используйте процедурные изображения для оценки vision-модуля «ремонт выполнен»: нужны 15–20 реальных пар с независимой разметкой специалистов.

## Ограничение API-импорта

`seed_backend.py` намеренно отдельный от `make data` и требует `--confirm IMPORT_SYNTHETIC_ORDERS`, admin-токен и локальный URL. Он может переносить только справочники и **новые выданные** наряды с будущими сроками; исходные события, даты и фото публичный API импортировать не позволяет. Подробности в корневом `README.md` этой папки и `INTEGRATION_GAPS.md`.
