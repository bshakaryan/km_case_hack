# Эталоны фазы 2

Все `*.json` здесь создаёт `python -m data_gen.generate`; метки задаёт **код**, а не LLM. `make eval` измеряет реализованные офлайн-сценарии фаз 4–6; результаты лежат в `reports/metrics.md` и `reports/metrics.json`. Это не экспертно подтверждённая точность.

| Файл | Кейсы | Что размечено |
| --- | ---: | --- |
| `verification.json` | 120 | Ровно по 30 вердиктов `accepted`, `accepted_with_remarks`, `needs_rework`, `needs_master_review`; категории: корректно, без фото, лишний материал, чужие работы, превышение времени, нет шифра, пограничный текст, неизвестный норматив |
| `deadlines.json` | 40 | Минутные тики, событие принятия, аварийный порог 3 мин, обычный 10 мин, предупреждение 30 мин, повторы 30 мин, руководитель через 90 мин, ожидаемые получатели/время/отсутствие дублей |
| `photos_dup.json` | 48 | Дубль/не дубль для точного совпадения, пережатия, кропа и другого рисунка; сами изображения появляются после `make data` |
| `intake.json` | 40 | Фраза → ID оборудования, участка, шифра, норматива и срок относительно фиксированного времени |
| `assistant.json` | 25 | Вопрос → инструмент, аргументы, численный ответ из снимка |
| `analytics.json` | 6+3 | Шесть заложенных сигналов и три однократные приманки из `data_gen/ground_truth/patterns.json` |

Сроковые эталоны покрывают весь 180-минутный таймлайн, включая повторы до последнего тика. В корректных карточках verification расход приведён к норме соответствующего шифра; `excess_material` превышает её намеренно.

Разметка проверки — **предположенная учебная политика**, а не утверждённое правило предприятия: отсутствие обязательного фото/шифра и явно чужая работа требуют доработки; перерасход/время дают замечание; неизвестное или неоднозначное — ручную проверку. В реальном backend отсутствие фото не допускает `complete` (HTTP 422); в синтетическом наборе карточка с таким дефектом существует только для офлайн-проверки рекомендаций и не означает, что API может её создать. Q02/Q03 в основном проекте остаются открытыми.

Изображения `photos_dup` показывают лишь способность находить технические повторы и **не** проверяют, что дефект устранён. Для vision-оценки и содержательной проверки работ нужны 15–20 реальных пар и независимые экспертные вердикты. Числа и приманки берутся из синтетических данных; качество на производстве этим набором не доказано.
