# НарядAI: итоговый аудит отдельного ИИ-сервиса

Дата: 7 октября 2026. Область аудита — только `ai_service/`, без изменений основного backend, frontend, mobile, Compose и схемы НарядAI. Статус: **воспроизводимый синтетический прототип, не готовый к производственной приёмке**. У сервиса есть отдельное API и собственное хранилище; существующий интерфейс его результаты автоматически не показывает.

## Выполнение кейса

| Требование | Что работает | Что пока не доказано или отсутствует |
| --- | --- | --- |
| 6.1 Контроль сроков | Детерминированный `tick(now)`, 30/10/3 мин, повторы, эскалация, кандидат замены, ключи идемпотентности | Доставка push/FCM, живое расписание смен, задержка и восстановление после сбоев в боевой нагрузке |
| 6.2 Проверка выполнения | Флаги полноты, материала и времени; четыре рекомендательных вердикта; структурированный LLM с повтором и fallback | Нормы материалов живого backend, экспертная точность смысловой проверки, автоматическая интеграция события сдачи |
| 6.3 Фото | SHA-256, pHash+SSIM, проверка прежних фото и времени загрузки, необязательная vision-рекомендация | Свежесть съёмки, 15–20 реальных экспертно размеченных пар, подтверждённая vision-accuracy |
| 6.4 Отчёты | Отчёт исполнителя/мастера/смены, PDF/XLSX, ручное переопределение оценки в собственной БД | Достоверные интервалы простоя и отображение отчёта в основном UI |
| 6.5 Аналитика | Шесть типов сигналов, разрезы, ссылки на наряды и рекомендации | Независимый holdout, доказанная причинность, автоматическая еженедельная рассылка |
| 6.6 Рейтинг | Шесть компонент, приоритет мастера, разложение балла, период | Утверждённые веса Q05, проверка справедливости на реальных оценках |
| 6.7 Ассистент | Четыре read-only инструмента, кодом рассчитанные ответы, максимум один вызов и 40 с | Авторизация мастера через основной backend, устойчивость на свободных вопросах, сохранённая очередь бонусных LLM-запросов |
| Ввод текста/голоса | Черновик с допустимыми ID, кодовый резолвер срока, STT за интерфейсом | Реальное аудио, независимая разметка, подтверждение черновика и создание наряда через UI |

ИИ **не** принимает наряд за мастера. `POST /ai/intake/text` и `/ai/intake/voice` наряды не создают. Производственные данные из `DATA_SOURCE=backend` теперь не отправляются во внешний LLM даже при наличии ключа; текстовый и vision-вызовы разрешены только на синтетике при явном `DEMO_MODE=false`. STT также включается только для синтетического режима, но реальное аудио нельзя считать обезличенным по одному факту такого режима — нужна организационная защита Q01.

Источник — фиксированный генератор, **не** независимые эксперты. Полные результаты, матрица ошибок и определения — [reports/metrics.md](reports/metrics.md) и [reports/metrics.json](reports/metrics.json).

| Вердикт по карточке | 120/120, accuracy/macro-F1 1,0/1,0 | Эталон следует той же учебной политике, что правила |

| Аномалии | 6/6 заложенных, 0/3 приманок | Есть ещё 2 неразмеченные гипотезы о ППР; причинность не доказана |
| Рейтинг | E-04 и E-11 в нижней трети | Веса предварительные, независимой проверки справедливости нет |
| Текстовый ввод | 40 шаблонов, точность пяти полей 1,0 | Не реальные формулировки и не распознавание аудио |
| Ассистент | 25 шаблонов, инструмент/число 1,0/1,0 | Не свободные вопросы и не LLM-оценка |

Неизвестно, а не ноль: реальная vision-accuracy, STT-accuracy, точность LLM-режима, доставка уведомлений, p95/стоимость внешних вызовов и качество на производстве. `make eval` по умолчанию **не** вызывает платные API. Три примера ошибок для модулей с нулём ошибок в этом наборе не выдумывались; дополнительные аналитические гипотезы приведены как нерешённые случаи.

## Риски и решение о внедрении

1. **P0 — права и передача данных.** Нужны backend gateway с серверной проверкой роли и наряда, отдельная read-only сервисная учётная запись, решение Q01 о данных/аудио и TLS. Сервисный `AI_SERVICE_TOKEN` нельзя помещать во frontend/mobile.
2. **P0 — качество решения.** Собрать реальные согласованные пары фото и карточки, разметить минимум двумя специалистами, разделить настройку порогов и holdout. До этого автоприёмка недопустима.
3. **P1 — события и инфраструктура.** Outbox/очередь из backend после фиксации сдачи, версионирование попытки, реальный канал push и наблюдаемость доставки. Бонусные LLM/STT-запросы сейчас асинхронны внутри HTTP-запроса, но не поставлены в сохраняемую фоновую очередь.
4. **P1 — доменные данные.** Нужны нормы расхода и связь шифра с нормативом, достоверные времена съёмки/остановки, календарь смен и история назначений. Q02–Q07 остаются открытыми там, где это указано в [INTEGRATION_GAPS.md](INTEGRATION_GAPS.md).
5. **P1 — развёртывание.** Конфигурация отдельного Compose проверена, но сборка Docker-образа была прервана при медленной загрузке пакетов; рабочий контейнер и нагрузка не подтверждены.

Решение: использовать для локальной демонстрации и дальнейшей интеграции **только как рекомендации**. Не обещать готовый push, качество ремонта по фото, полную мобильную интеграцию или производственную точность.

## Воспроизведение и состояние репозитория

Из `ai_service/`: `python -m data_gen.generate`, `python -m eval.run`, `python -m pytest -q tests`, `docker compose -f docker-compose.ai.yml config --quiet`. Windows без `make` поддерживается. Для ручной демонстрации — [DEMO.md](DEMO.md). Существующий backend и его миграции не запускались в рамках оценки.

Итоговый прогон: **48 тестов прошли, 1 не прошёл**. Охранный `tests/test_repo_untouched.py` продолжает находить 25 отслеживаемых изменений вне `ai_service/`, существовавших до этой работы; поэтому полный `make test` не зелёный. Владелец отдельно разрешил коммиты **только `ai_service/`** при таком состоянии. Внешние файлы не сбрасывались и не включались в коммиты.
