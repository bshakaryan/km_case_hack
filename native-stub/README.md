# Заглушка нативного клиента

Нативная часть намеренно ограничена TypeScript-контрактами и адаптерами для будущего приложения **React Native**. Здесь нет собранного Android/iOS-приложения, эмулятора, React Native runtime, фоновой синхронизации и настоящих push-уведомлений. Для демонстрации действий работника доступна веб-панель под логином `worker`.

- `src/api.ts` — настоящий HTTP-клиент к существующему FastAPI: авторизация, наряды, статусы, завершение, уведомления, загрузка фото. Он не отправляет запросы автоматически при импорте.
- `src/types.ts` — типы публичного контракта.
- `src/native.ts` — явно помеченные заглушки камеры, регистрации push и непостоянной очереди. Камера сообщает, что не реализована; push возвращает `registered: false`. Очередь хранится только в памяти и сама ничего не отправляет.
- `src/example.ts` — пример загрузки будущего экрана работника с переданными пользователем адресом сервера и учетными данными.

В будущем нужно создать React Native проект, подключить экраны к `NaryadApi`, добавить безопасное хранение токена в Keychain/Keystore, разрешения камеры, сжатие снимков перед отправкой, локальную БД для офлайн-операций и серверную идемпотентность с разрешением конфликтов. Реальные уведомления требуют FCM/APNs и серверной регистрации токенов устройств. Никакой из этих интеграций текущий код не имитирует как работающую.

Адрес API для физического устройства должен быть доступен по сети: `http://<IP-компьютера>:8080`. `localhost` на телефоне указывает на сам телефон. В production нужен HTTPS. Передавайте адрес сервера без `/api` — клиент добавляет префикс сам.

Типы можно проверить установленным компилятором веб-панели из корня проекта:

```bash
./frontend/node_modules/.bin/tsc -p native-stub/tsconfig.json
```
