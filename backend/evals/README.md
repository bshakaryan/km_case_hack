# Синтетический набор для проверки ИИ-сдачи

Здесь **не производственные фотографии**. Пять PNG созданы встроенным инструментом генерации изображений 7 октября 2026 года: исходная течь фланца синего насоса, сухой фланец после ремонта (редактирование исходного фото), продолжающаяся течь (редактирование исходного), чужой электрический шкаф и размытое фото после ремонта (редактирование сухого). Файлы находятся в `photos/`; для повторного снимка используется тот же исходный файл. Генерация выполнялась по описаниям промышленного узла без людей, текста и логотипов.

`cases.json` содержит семь сценариев: видимое исправление, неисправность после ремонта, недостаточный отчёт, чужое оборудование, точный дубликат, нечёткий снимок и честный отчёт о сохранившемся дефекте. `expected_verdict` и `rationale` — **предварительная синтетическая разметка автора набора**, не экспертное заключение. Фото не доказывает герметичность под нагрузкой, время съёмки, факт замены прокладки или принадлежность снимка конкретному реальному оборудованию. До заявления о точности на предприятии два независимых мастера должны оценить случаи по одной рубрике и разрешить расхождения; нужны реальные разрешённые данные и более разнообразный отложенный набор. Пока решение Q01 о передаче производственных фото внешнему API не принято, используйте только синтетические данные.

Из `backend/`:

```powershell
python -m evals.run
python -m evals.run --live
```

Первый запуск проверяет целостность JSON и PNG без сети и без API-расходов. `--live` создаёт временную SQLite-базу с демоданными, проводит каждый кейс через настоящие HTTP-маршруты создания наряда, загрузки фото, сдачи и фоновую проверку, затем сохраняет `results/latest.json`. В одноразовой БД имитируется 65 минут работы, иначе моментальная тестовая сдача передаст модели нулевую длительность. Локальный `.env` загружается для ключа; содержимое ключа не выводится. В Docker после `docker compose up -d --build backend` можно использовать `docker compose exec backend python -m evals.run --live`; JSON остаётся внутри контейнера, а результаты печатаются в консоль. Для сохранения JSON на хосте используйте локальный Python или `docker cp`.

Отчёт показывает долю точных совпадений, precision/recall/F1 по трём вердиктам и число опасных `passed` при ожидаемом ином ответе. На семи синтетических кейсах это **регрессионный индикатор, не статистически надёжная accuracy**. Повторяйте прогон после изменения промпта/модели и сравнивайте с прежним результатом. Числовой балл 1–5, `confidence`, аналитика, ассистент и подсказки шифра этим набором пока не оцениваются: им нужны отдельные эталоны.
